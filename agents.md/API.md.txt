# API.md

# Trinova Landing Page & Digital Growth Platform

Dokumen ini mendefinisikan seluruh API internal maupun eksternal yang digunakan oleh aplikasi.

Project ini berorientasi pada **Server Rendered Application (Laravel + Livewire)** sehingga API bukan menjadi jalur utama komunikasi aplikasi.

API hanya digunakan apabila benar-benar diperlukan.

---

# API Philosophy

Prioritas komunikasi aplikasi:

```
Livewire

↓

Service

↓

Repository

↓

Database
```

Gunakan API hanya apabila:

- dibutuhkan oleh aplikasi pihak ketiga
- dibutuhkan oleh Mobile Apps
- dibutuhkan integrasi eksternal
- dibutuhkan AJAX yang kompleks
- dibutuhkan webhook

Jangan membuat API hanya karena bisa.

# Response Format

Semua response menggunakan format yang konsisten.

## Success

```json
{
    "success": true,
    "message": "Success",
    "data": {}
}
```

---

## Validation Error

```json
{
    "success": false,
    "message": "Validation Error",
    "errors": {}
}
```

---

## Server Error

```json
{
    "success": false,
    "message": "Internal Server Error"
}
```

# Internal Service Flow

Semua endpoint harus mengikuti alur berikut.

```
API Route

↓

Controller

↓

Form Request

↓

Service

↓

Repository

↓

Model

↓

Database
```

Controller tidak boleh berisi business logic.

---

# Validation Rules

Semua endpoint wajib menggunakan:

```
Form Request
```

Tidak boleh melakukan validasi langsung di Controller.

---

# Authorization Rules

Gunakan:

- Policy
- Gate
- Middleware

Jangan melakukan pengecekan role secara manual di Controller.

---

# Rate Limiting

Public API

```
60 request / menit / IP
```

Authentication API

```
120 request / menit / user
```

Gunakan Laravel Rate Limiter.

---

# Error Handling

Gunakan HTTP Status Code yang sesuai.

| Status | Arti |
|---------|------|
| 200 | Success |
| 201 | Created |
| 400 | Bad Request |
| 401 | Unauthorized |
| 403 | Forbidden |
| 404 | Not Found |
| 422 | Validation Error |
| 500 | Internal Server Error |

Jangan pernah mengembalikan stack trace ke client.

---

# API Coding Rules

Selalu gunakan:

- Form Request
- Service Pattern
- Repository Pattern
- Resource Class untuk response JSON
- Pagination untuk data list
- Eager Loading untuk relationship

Hindari:

- Query di Controller
- Query di Resource
- Business Logic di Controller
- Raw SQL tanpa kebutuhan khusus

# Final Principle

Aplikasi ini bukan API First.

Aplikasi ini adalah **Conversion First**.

API dibuat hanya apabila benar-benar memberikan nilai terhadap:

- Conversion
- Integrasi
- Skalabilitas
- Otomatisasi

Apabila suatu fitur dapat diselesaikan dengan Livewire atau Server Side Rendering secara lebih sederhana, maka gunakan pendekatan tersebut dibanding membuat endpoint API baru.
